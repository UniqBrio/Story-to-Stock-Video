# Production Audit — Story-to-Stock-Video (SVOS)
*2026-09-07 · audit only, no code changed · verified against the implementation, not the documentation*

---

## Executive summary

The render layer is production-grade. The platform does not exist yet.

`grep` across every `.py` file finds **zero LLM/AI API calls**, no ASR, no TTS, no image/video generation, no HTTP server, no database, no queue, no cache, no auth, no object storage, no test directory, no CI, and no git repository. The two sibling folders `Story-to-Stock-Video_Didn't work out\` and `Story-to-Stock-Video_ToBeTried\` are empty.

What actually exists is two disconnected halves:

| Half | Form | Executed by |
|---|---|---|
| **Creative decision layer** — script → beats → treatments → shot list → search queries → overlay copy → timing | ~10 Markdown documents here + 395 skill `.md` files in `..\Pull-skill-research-MultiLLMs\output\` | A human, in a chat window, by hand |
| **Render layer** — shot list → MP4 + QA report | 15 Python files, 5,794 lines, stdlib + openpyxl + Pillow + FFmpeg 8.1 | `python run_pipeline.py story_plan.xlsx` |

The handoff between them is a **hand-typed Excel file**. Every creative decision in the finished video — how long each shot runs, which treatment it gets, what the overlay says, when it appears, what to search for — is typed into `story_plan.xlsx` by a person. The code renders those decisions faithfully and to broadcast spec. It makes none of them.

So the honest answer to "is the output publish-ready?" is: **it is as good as whoever filled in the spreadsheet.** The system has no opinion about viewer retention, visual relevance, or pacing, because it has no code that forms one.

That is the gap this audit is about. Everything below is organised around closing it without discarding the render layer, which is the part that works.

## Phase 1 — The actual execution path

Traced by reading every file and by running the pipeline end-to-end (`selftest.py`, 7 shots, 19 assertions, passes in ~80 s).

```
  story_plan.xlsx                        ← a HUMAN types every creative decision here
        │
        │  openpyxl, header-name mapping, enum validation, restraint audit
        ▼
   project.json                          ← the ONLY state store. No DB. No job record.
        │                                   Each phase load→mutate→save the whole file.
        ▼
  ┌─ 2 asset_fetcher.py ─────────────────────────────────────────────┐
  │   urllib → Pexels / Pixabay / Unsplash REST                      │
  │   scoring = resolution + aspect + duration-fit + query-rank      │
  │   NOTHING LOOKS AT THE PICTURE                                   │
  │   → Assets/Videos, Assets/Images  + license string per asset     │
  └──────────────────────────────────────────────────────────────────┘
        ▼
  3 clip_normaliser.py   one ffmpeg per shot → exact-duration clip
                         T1 card = flat colour · T5 = logo card · T4 = blurred letterbox
                         arc grade + ONE unified finishing grade + optional grain
        ▼
  4 transition_engine.py single filter graph: concat cut-runs, xfade the rest
                         → assembled_raw.mp4 + the AUTHORITATIVE TIMELINE
        ▼
  5 overlay_engine.py    one drawtext pass, timed from that timeline
                         PIL-measured auto-fit · safe zones · rise/fade · Tamil
        ▼
  6 audio_mixer.py       silencedetect on VO → duck map → amix(normalize=0)
                         → 2-pass loudnorm → −14 LUFS / −1.5 dBTP
        ▼
  7 final_export.py      H.264 High@4.2 · BT.709 · 2 s GOP · faststart
                         + cover frame + render_manifest.json
        ▼
  8 qa_check.py          ffprobe · ebur128 · blackdetect · freezedetect · silencedetect
                         + heuristic editorial checks → qa_report.md
        ▼
   final_video.mp4       verdict: READY FOR G6 REVIEW  (a human still decides)
```

**Verified render-layer facts** (from the last self-test run): 25.00 s output, 1080×1920, 30 fps, h264 High, yuv420p, AAC 48 kHz stereo, −14.0 LUFS integrated, −1.3 dBTP true peak, transition overlaps correctly subtracted (shot 003 starts at 6.5 s, not 7.0 s), Tamil rendered via Nirmala UI, T4 product-insert overlay correctly dropped, 3 s source correctly held to a 4 s shot.

**What is NOT in the execution path, verified by grep:** ASR · LLM · TTS · image generation · video generation · captions · music selection · SFX · scene planning · vision scoring · caching · queueing · retry budgets · cost metering · structured logs · tests beyond one smoke test.

`prompt_generator.py` and `bgm_prompt_generator.py` are not AI integrations. They render *prompt text into an HTML page* for a human to copy into ChatGPT / Gemini / Suno in a browser, then save the file back by hand. There is no API call and no return path.

## Phase 2 — Audit findings

### 2.1 Functional gaps (missing, not broken)

| Area | Gap | Why it matters |
|---|---|---|
| Input | No ASR. The brief says "entered or spoken"; nothing accepts speech | The spoken-input product promise is unimplemented |
| Understanding | No LLM anywhere. No script segmentation, no beat detection, no entity/number extraction | The system cannot reason about the script |
| Planning | No scene planner. Treatment, duration, motion, transition and overlay copy are hand-typed | This is the human bottleneck; ~15 min of gate time is really hours of sheet-filling |
| Voice | No TTS. `vo_path` must be a file the user produced elsewhere | Blocks unattended generation |
| Visuals | No AI image/video generation in-process | The "AI visuals" arm is a separate browser-RPA project (`..\Image_generation_automation_ChatGPT\`) not wired in |
| Captions | **No subtitle generation at all** | QA tests "sound-off comprehension" but nothing produces the captions that would pass it. Most social viewing is muted |
| Formats | One aspect ratio per run; no reframing intelligence | 1:1 and 16:9 variants require a full re-render and centre-crop faces out of frame |
| Music | No library, no selection logic — one BGM file the user supplies | No emotional matching, no swell at the CTA |
| Sound design | No SFX layer, no whooshes on cuts, no room tone | Flat mix; the ear notices |
| Curation | No vision scoring. The curation skill's 6-axis rubric is unimplemented | Relevance is unenforced — the #1 driver of "does this feel intentional" |
| Dedupe | Only same-asset-ID dedupe; no perceptual similarity | Two different IDs of the same stock shoot read as a repeat |
| Caching | No cache of API responses or downloads | `--contact-sheet 8` on 12 shots is up to ~216 API calls, repeated on every re-run |
| Platform | No queue, worker, job record, idempotency key, or concurrency | Cannot serve a second user or survive a crash mid-job |
| Observability | One FFmpeg text log; no metrics, no cost meter, no job status | Cannot debug a failure you did not watch happen |
| Testing | One smoke test, one scenario, 19 assertions | No coverage of script archetypes, long scripts, or degraded inputs |
| Version control | Not a git repository | No history, no rollback, no review, no CI |

### 2.2 Bugs and fragilities (verified by reading the code)

| # | File | Issue | Severity |
|---|---|---|---|
| B1 | `asset_fetcher.py:99` | Download validation is a `> 10 KB` size check only. No `Content-Type` check, no `ffprobe` verification. A large error page or a truncated file passes and fails later, in a different phase, with a confusing message | High |
| B2 | all | `project.json` is read-modify-written whole-file by every phase. Two concurrent runs, or an editor with the file open, silently lose writes. No lock, no schema-version check on load | High |
| B3 | `clip_normaliser.py`, `transition_engine.py` | A shot whose source is missing is **dropped from the assembly**, silently shortening the video. The VO then runs past the picture. Console prints a warning; `qa_check` catches the length delta only if `assembled_duration` was written | High |
| B4 | `asset_fetcher.py` | Assets supplied by hand in `Local File Path` get **no licence record**, and `qa_check` only warns for the three known API sources — so the one case most likely to carry a licence problem is the one case with zero tracking | High (legal) |
| B5 | `audio_mixer.py:80` | The duck expression nests one `max()` per detected speech segment and runs `eval=frame`. Tested at 8 segments. An 83 s VO has ~35 — expression length and per-frame eval cost are unmeasured at that scale | Medium |
| B6 | `audio_mixer.py:39` | `silencedetect` threshold is hard-coded at −35 dB with no calibration to the recording's own noise floor. A quiet or roomy VO produces a wrong speech map, so the music ducks in the wrong places | Medium |
| B7 | `asset_fetcher.py:88` | On three consecutive 429s, the error string is built from a possibly-unbound local guarded by `'last' in dir()`. Works, reports "unknown" | Low |
| B8 | `overlay_engine.py:203` | `logo_windows()` zips `timeline` against a re-filtered shots list, assuming identical ordering. Correct today; silently misaligns if IDs ever duplicate | Low |
| B9 | `clip_normaliser.py:89` | `zoompan` oversamples stills to 2× output (2160×3840) with no guard on source resolution. A 40 MP still spikes memory | Low |
| B10 | `asset_fetcher.py` | `--force` is accepted and ignored (a compatibility shim); only `--refetch` re-downloads. A user passing `--force` expecting a refresh gets silence | Low |
| B11 | `story_reader.py`, `asset_fetcher.py` | `openpyxl.load_workbook` + `save` round-trips the user's sheet, discarding charts, images and conditional formatting if any are ever added | Low |
| B12 | `qa_check.py:79` | Dead code (`if vf and not af: pass`) | Cosmetic |

### 2.3 AI / LLM problems

There is no LLM, so the failure modes are inverted — everything an LLM would do is either absent or done by a hard-coded heuristic:

- **Arc position is index-based.** `prompt_generator.py` and `bgm_prompt_generator.py` both classify a shot as setup/rising/resolution by its *position in the list* (`pct < 0.34`). A story whose pivot lands at 20 % is mis-analysed, and the BGM brief inherits the error.
- **Demographic assumption is hard-coded.** `prompt_generator.build_prompt()` injects `"A South Indian person, natural warm medium-brown skin tone…"` whenever any of ~18 words (`person`, `phone`, `parent`, `crowd`…) appears in the scene text — including for shots meant to be a close-up of hands or an empty desk. It fires on the word, not the intent.
- **Grade → mood is a 4-entry lookup.** `chaos/pivot/cta/none` is the entire emotional vocabulary the system understands.
- **No structured outputs, no schema validation, no retry, no fallback model, no context management** — because there is no model.

### 2.4 Visual problems

- **Pacing is whatever was typed.** No content-aware duration. A dense number line and a mood beat both get whatever the human guessed.
- **One motion vocabulary.** `zoom_in / zoom_out / pan_left / pan_right` at a fixed 7 % (video) or 18 % (stills). Over 83 s every shot moves the same way — this reads as a template.
- **Centre crop only.** No subject detection, so landscape stock cropped to 9:16 cuts heads and off-centre subjects out of frame.
- **Four overlay styles.** `caption / keyword / card / cta`. The `text-on-screen-system` skill specifies lower-thirds, stat treatments, lists, callouts, quotes, and in-line emphasis; none are rendered.
- **No anchor-word emphasis.** A line is one colour. The skill's central idea — the one word in Brio Orange inside a white line — cannot be expressed.
- **No charts, no diagrams, no stat cards.** For content built on rupee arithmetic ("₹47,000. Gone. Every year."), a designed number is the highest-value visual in the whole system, and it does not exist beyond a plain text card.
- **No B-roll interleaving, no cutaways, no pattern interrupts, no j/l cuts.** Shot changes only ever happen at line boundaries.
- **No continuity scoring.** Adjacent clips from different shoots, lighting directions and wardrobes are joined with no check; the unified grade papers over colour but not content.

### 2.5 Stock-media problems

- **The Pexels key is dead — HTTP 403.** Verified live. Pexels is the best free source for portrait video; the system silently degrades to Pixabay and Unsplash and nothing in the output says so.
- **Ranking never looks at a frame.** Resolution, aspect fit, duration fit, query rank, source. A Western open-plan office and an Indian academy score identically.
- **Query generation is manual.** The four-lane strategy (literal / emotional / metaphorical / India-specific) lives in the curation skill; the code runs whatever comma-separated phrases were typed.
- **No negative keywords.** No way to exclude "whiteboard", "handshake", "Western office".
- **No diversity constraint.** Nothing prevents two adjacent shots from the same creator, location or shoot.
- **No rate-limit budget and no cache.** Every re-run pays the full API cost again.
- **Licensing** is recorded correctly for API-sourced assets (source, ID, author, page URL, licence text → `project.json`, the Asset Tracker sheet, and `render_manifest.json`). It is absent for hand-added files (B4) and for AI-generated images, which also carry no "AI-generated" provenance — a growing platform-disclosure requirement on Meta and TikTok.

### 2.6 Audio

Strong foundation (duck map, −14 LUFS two-pass, 48 kHz, sting placement), with these gaps: fixed silence threshold (B6), binary duck rather than per-scene duck percentages, no music selection, no SFX, no VO quality checks (clipping, plosives, sibilance, room tone), and — most importantly — **no per-word alignment**, which is what blocks both captions and automatic overlay timing.

### 2.7 QA

`qa_check.py` covers technical spec, loudness, black frames, frozen picture, dead air, and heuristic editorial rules (word counts, CTA regex, restraint budgets, hook window). What it cannot do:

- Check text contrast **against the actual pixels behind it** (it checks the setting, not the result).
- Detect repeated compositions, blur, or low-detail assets.
- Verify safe-zone compliance on the rendered frame rather than in the layout maths.
- **Repair anything.** It reports and exits; there is no regenerate loop.
- Produce a score.

### 2.8 Performance, reliability, security, cost

- **Five full re-encodes** per video (normalise → assemble → overlay → audio mux → final). Two are avoidable by merging the overlay pass into the assembly graph and stream-copying the mux.
- **Fully sequential.** No parallel shot normalisation, though shots are independent — the obvious 4× win.
- **No per-scene failure isolation.** A failure either stops the run or silently drops a shot (B3). Neither is graceful degradation.
- **No disk-space check** before a render that writes several GB of intermediates.
- **Live API keys are committed** in `project.json` and stored in `story_plan.xlsx`. Treat all three as leaked and rotate.
- **Injection surface is small and handled:** `subprocess` is called with argument lists (never `shell=True`) and sheet text is escaped before entering filter strings. File paths from the sheet are passed to FFmpeg unvalidated — acceptable single-user, unacceptable multi-tenant.
- **No cost controls:** no per-job budget, no model-call cap, no download cap, no quota.

## Phase 5 — Target architecture

The structural move is one sentence: **keep the render layer, and replace the spreadsheet with a Scene Plan JSON contract.** Excel then becomes one of several front-ends rather than the system's brain.

```
  ┌── INGEST ────────────────────────────────────────────────────────┐
  │  text | audio                                                    │
  │  audio → ASR → transcript + WORD-LEVEL TIMINGS                   │
  │  → normalised Script object                                      │
  └──────────────────────────────────────────────────────────────────┘
                              ▼
  ┌── UNDERSTAND (LLM, structured output, schema-validated) ─────────┐
  │  beats · intent per beat · entities · numbers · emotional arc    │
  │  · anchor words · hook candidates · CTA                          │
  └──────────────────────────────────────────────────────────────────┘
                              ▼
  ┌── PLAN ──────────────────────────────────────────────────────────┐
  │  LLM proposes, DETERMINISTIC SOLVER disposes:                    │
  │    treatment per beat (stock · AI · typography · stat · chart ·  │
  │      screen · logo)   with a stated REASON                       │
  │    duration from the pacing engine (density × beat × platform)   │
  │    motion + transition, with variety constraints                 │
  │    restraint budgets · AI-visual policy · hook rules             │
  │  → SCENE PLAN JSON  ← the contract. Human-reviewable at G3.      │
  └──────────────────────────────────────────────────────────────────┘
                              ▼
  ┌── SOURCE ────────────────────────────────────────────────────────┐
  │  4-lane query planner → provider adapters (cache, retry, budget) │
  │  → candidate pool → FRAME EXTRACTION → vision scorer (6 axes)    │
  │  → licence gate (hard block on unknown) → pick + backup          │
  │  AI generation only where the policy engine allows it            │
  └──────────────────────────────────────────────────────────────────┘
                              ▼
  ┌── COMPOSE (deterministic — no LLM below this line) ──────────────┐
  │  design tokens → layout engine → SVG/PNG overlay layers          │
  │  captions from word timings · stat cards · charts · lower-thirds │
  └──────────────────────────────────────────────────────────────────┘
                              ▼
  ┌── RENDER  ← the existing, working FFmpeg layer, fewer passes ────┐
  └──────────────────────────────────────────────────────────────────┘
                              ▼
  ┌── VERIFY ────────────────────────────────────────────────────────┐
  │  technical + perceptual + editorial checks → QUALITY SCORE       │
  │  → REPAIR LOOP (regenerate the failing scene, bounded)           │
  └──────────────────────────────────────────────────────────────────┘
                              ▼
  ┌── DELIVER ───────────────────────────────────────────────────────┐
  │  9:16 · 1:1 · 16:9 variants · captions (.srt) · cover frame      │
  │  · licence manifest · publish package                            │
  └──────────────────────────────────────────────────────────────────┘

  PLATFORM SHELL: job queue · worker pool · object storage · job records
                  · cost meter · structured logs · idempotency
```

Two principles worth stating explicitly, because they decide most design arguments downstream:

1. **LLM above the Scene Plan, deterministic below it.** Creative judgement (what should this beat show, and why) is a reasoning problem. Layout, typography, safe zones, timing arithmetic and rendering are not — they must be reproducible, testable, and identical on every run.
2. **Every scene carries a reason.** The Scene Plan stores *why* each treatment was chosen. That is what makes the QA repair loop possible, makes the video reviewable at a gate, and is the difference between an editorial system and a slideshow generator.

## Phase 6 — Top 10 improvements by impact on the finished video

Ordered by how much each one changes what a viewer actually sees.

| # | Improvement | Backlog | Why it ranks here |
|---|---|---|---|
| 1 | **Burned-in captions from word-level alignment** | VD-04, VD-09 | Muted viewing is the default on every target platform. Today the video is incomprehensible without sound, and QA tests for a property nothing produces |
| 2 | **Scene planner producing a Scene Plan JSON** | VD-06 | Removes the human bottleneck and is the precondition for pacing, variety, repair, and every other item below |
| 3 | **Vision-scored asset selection** | VD-08, VD-14 | Visual relevance is the single largest contributor to "this feels intentional". Metadata scoring cannot tell an Indian academy from a Western office |
| 4 | **Stat cards, quotes and charts as first-class visuals** | VD-10, VD-11 | The content is rupee arithmetic. A designed number outperforms any stock clip, and this is the cheapest large win in the list |
| 5 | **Content-aware pacing + hook engineering** | VD-12 | Fixed durations produce either monotony or rush. The first 1.5 s decides whether anything else matters |
| 6 | **Motion and composition variety guard** | VD-15 | Four Ken Burns moves applied uniformly is the clearest tell of template output |
| 7 | **Subject-aware reframing + multi-format export** | VD-13 | Stops cropping heads, and turns one render into three publishable formats |
| 8 | **QA → repair loop and a quality score** | VD-16, VD-17 | Converts QA from a report into a mechanism. "Rendered successfully" stops being the delivery signal |
| 9 | **Licensing provenance + AI-visual policy** | VD-01, VD-20 | Removes legal exposure, and the AI cap is what keeps the output from reading as an AI demo |
| 10 | **Fix the dead Pexels key and make provider failures loud** | VD-03, VD-07 | One expired credential is currently degrading the footage in every video, silently |

Items 1, 4, 9 and 10 are small or medium effort and can land before the planner. Item 2 is the large one, and everything from 3 onward is easier once its JSON contract exists.

### Status update — 2026-09-30 (U-rated content safety)

Requirement: all content (stock, AI-generated, own uploads such as product recordings and the logo; visible
text, voiceover and spoken audio, captions) must be suitable for children, reviewed and validated before it
is used or published. Swimwear-type subjects must use cartoon / illustrated / animated visuals only, with no
real or celebrity faces.

| Area | Status | What changed |
|---|---|---|
| Automated screening | **Closed** | `content_safety.py` runs local models only: CLIP ViT-B/32 ONNX zero-shot for categories and photo-vs-cartoon style, NudeNet, RapidOCR, Whisper small via sherpa-onnx, and an English, Tamil and Tanglish blocklist. Models are downloaded by `--setup` and verified by SHA-256. |
| Gates | **Closed** | An asset gate runs before Phase 3 and a final-video gate after Phase 7, per shot. The fetcher screens every download and every contact-sheet preview. `clip_normaliser`, `transition_engine`, `overlay_engine` and `audio_mixer` refuse anything not cleared for its exact content hash and use. Preflight is critical when models or packages are missing, or when text fails. |
| Human review | **Closed** | REVIEW items need a recorded approval and FAIL items must be replaced; an override needs a written reason and is logged. The final report requires a named sign-off tied to the video's SHA-256. QA reports **critical** while items are open and **major, do not publish** without the sign-off. The sign-off is stamped into `render_manifest.json`. |
| Cartoon-only subjects | **Closed** | Phase 1 flags swimwear-type shots. The fetcher uses only Pixabay `video_type=animation` and `image_type=illustration`. AI prompts are cartoon-style with modest full-coverage swimwear and no real or celebrity likeness. Real photos (photo score ≥ 0.60) and real faces fail. |
| Stock filters | **Closed** | Pixabay `safesearch=true` (unchanged) and Unsplash `content_filter=high`. Pexels has no filter, which is why every download is screened. |
| AI prompts | **Closed** | Every prompt asks for modest, age-appropriate, family-friendly content and excludes nudity, revealing clothing, alcohol, smoking, weapons, violence and celebrity likeness. |

Whisper small transcribes English accurately. Tamil is approximate, so the report asks for a listen.

**False-positive fix, 2026-10-07 (policy `u-rated-2026-10-07.1`).** On real UniqBrio stock, an exhausted teacher slumped over books scored CLIP "nudity" up to 0.61, because the nearest prompt was "a person in a sexually suggestive pose". Hands holding a phone scored 0.32. A woman in a buttoned shirt raised NudeNet `FEMALE_BREAST_COVERED` 0.68, which this policy treated as "revealing clothing?".

- Fourteen everyday posture and close-up prompts were added to the safe list. None sits closer to an unsafe prompt in CLIP text space (max 0.874) than the existing safe prompts (0.907).
- NudeNet "covered" detections now ask for review only when CLIP's swimwear/lingerie score is at least 0.15.
- On the five project clips, the peak nudity score went from 0.61 to 0.09, and all five pass. Cartoon swimwear still fails in normal shots, and real photos still fail in cartoon-only shots.
- Policy `u-rated-2026-10-07.2`: a phone edge over a spiral notebook scored "a knife or blade" (weapons 0.43, in one of five frames). Desk-object prompts were added to the safe list (max text similarity to an unsafe prompt 0.845). In video, a review-level weapons, violence, alcohol, drugs or horror hit seen in only one frame is dropped as a misreading and noted. Two frames, any fail-level hit, and any nudity or swimwear hit still count.
- Whisper output on music is no longer a hallucinated token loop. Text is dropped when P(no speech) > 0.6, when the average log-probability is below −1.0, or when it contains no real word. Non-speech tokens are suppressed and repetition loops are cut. Limit: low-confidence sung lyrics are dropped rather than guessed, so the human listen at sign-off still covers music with vocals.
